# Конвенции хранилища

Общие правила для всех заметок. Детали по типам — в соседних файлах (`theory-note.md`, `chord-note.md`, `song-analysis.md`).

## Именование файлов

- `Интервалы/<короткое-обозначение> <название>.md`, напр. `Интервалы/P5 Чистая квинта.md`
- `Тональности/<Тоника> <major|minor>.md`, напр. `Тональности/C major.md`, `Тональности/A minor.md`
- `Аккорды/<Символ аккорда>.md`, напр. `Аккорды/C.md`, `Аккорды/Am.md`, `Аккорды/F.md`
- `Песни/<Исполнитель> — <Название>.md`
- `Мелодии/<Название>.md`, напр. `Мелодии/Спуск по Gm.md`
- `Теория/<Название понятия>.md`, напр. `Теория/Ступени.md`

Аккорды и тональности называются по-разному не просто так: у аккорда символ короткий и уникальный (`C`, `Am`, `F`), у тональности — полное английское название (`C major`, `A minor`). Это исключает совпадение имён файлов между папками `Аккорды/` и `Тональности/` — иначе `[[C major]]` было бы неоднозначной ссылкой. Русское название добавляется внутри заметки (в теле или свойстве `name`), а не в имени файла.

## Frontmatter по типам

```yaml
# интервал (Интервалы/)
type: interval
short: P5
semitones: 7
mastered: false

# тональность (Тональности/)
type: key
tonic: C
mode: major   # major | minor
name: До мажор   # русское название
mastered: false

# аккорд (Аккорды/)
type: chord
root: C
quality: major   # major | minor
name: До мажор    # русское название
mastered: false

# песня (Песни/)
type: song
artist: ...
key: "[[C major]]"
capo: 0
tempo_bpm: null
mastered: false

# мелодия (Мелодии/)
type: melody
key: "[[G minor]]"
frets: 3–7
tempo_bpm: null
source: своя находка
mastered: false

# понятие теории (Теория/)
type: theory
mastered: false   # "разобрался / нет", ставит Иван сам
```

Плюс во всех типах — необязательные поля журнала тренировок, их ставит агент по `practice-log.md`:

```yaml
last_practiced: 2026-08-02   # дата последней тренировки
practice_min: 45             # суммарно минут
```

Отсутствие этих полей = "ни разу не тренировал", отдельный вид в `Дашборд.base` их и показывает. Не проставляй их заранее нулями.

Поле `name` у интервалов/песен не обязательно — если не задано, используется имя файла. У аккордов и тональностей `name` обязателен и хранит русское название, потому что в дашборде удобнее видеть "До мажор", чем "C".

## Формат тела заметки

- Заголовки — только если реально нужна навигация (в песнях и в тональностях, где много секций подряд — гамма, аккорды, гриф, пентатоника). В интервалах/аккордах/теории — просто таблицы и диаграммы без "простыни" заголовков, там одной-двух секций достаточно, чтобы не заблудиться.
- Диаграммы грифа — ASCII в блоке кода, одна строка = одна струна, сверху вниз `e B G D A E` (от тонкой к толстой), `x` = не играется, число = лад, `0` = открытая струна.
- Любой аккорд/тональность, упомянутые в теле заметки (особенно в песнях), оформляй как `[[Wikilink]]` — это единственный способ вести учёт "где используется" без ручного дублирования.

## Base-файлы

В каждой из папок-тем — свой `.base` (напр. `Аккорды/Аккорды.base`) с фильтром `type == "..."` и колонкой `mastered`. Корневой `Дашборд.base` агрегирует все типы через `groupBy: type`. При добавлении нового свойства в заметки проверяй, что фильтры/order в `.base` не сломались (Bases — YAML, синтаксис см. https://obsidian.md/help/bases).

## Прогресс

`mastered` двигает только Иван вручную (галочка в свойствах заметки). Агент может предложить, что уже похоже на освоенное, но не должен сам менять это поле без явной просьбы.
