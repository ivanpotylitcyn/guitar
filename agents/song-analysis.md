# Протокол: разбор песни (`Песни/`)

Это самая ценная часть хранилища для Ивана. Цель — не "аккорды над текстом" (это позволяет играть не думая), а **разбор песни на составляющие**: тональность, ноты, последовательности аккордов, темп, мелодия, соло. Аккорды над строками текста считаются анти-паттерном здесь и не используются.

## Frontmatter

```yaml
type: song
artist: ...
title: ...            # если отличается от имени файла
key: "[[C major]]"      # ссылка на заметку тональности
capo: 0
tempo_bpm: null       # если не удалось определить — null, не гадать
source_url: ...       # запись/табы, по которым делался разбор
mastered_chords: false
mastered_rhythm: false
mastered_vocals: false
mastered_solo: false
mastered: false       # общий статус, ставит Иван сам
```

## Обязательные секции тела

### 1. Обзор
Тональность (`[[key]]`), капо, темп (BPM), жанр/характер одной строкой.

### 2. Прогрессии по секциям
Таблица на каждую структурную секцию (Verse/Chorus/Bridge/...), **и буквами, и римскими цифрами** одновременно:

| Секция | Аккорды | Ступени |
|---|---|---|
| Verse | [[C]] – [[G]] – [[Am]] – [[F]] | I – V – vi – IV |
| Chorus | ... | ... |

Аккорды — всегда `[[Wikilink]]` на заметку в `Аккорды/`. Если непонятно, что значат римские цифры (I, V, vi...) — см. `Теория/Ступени.md`.

### 3. Текст
Текст песни — **отдельным блоком, без аккордов внутри строк** (аккорды уже разведены в таблице секций выше). Можно пометить справа от строки, к какой секции она относится, если это не очевидно.

### 4. Вокальная мелодия
Построчная транскрипция нот мелодии (нота на каждую строку/фразу текста) + диапазон (нижняя–верхняя нота) отдельной строкой сверху.

| Строка текста | Ноты |
|---|---|
| ... | C4 D4 E4 ... |

### 5. Соло / проигрыши
Для каждого инструментального фрагмента:
- тональность/лад и зона на грифе (лады),
- разбор фразы: сколько всего нот, сколько из них уникальных, какие интервалы между соседними нотами преобладают.

## Критично: не выдумывать

Если разбор делается не по реальной прослушанной/подтверждённой записи (нет доступа к аудио, нет точных нот) — **не сочинять точные ноты и прогрессии**. В этом случае:
- ставить `?` или "не определено" в соответствующих полях/ячейках,
- явно писать в `source_url` / рядом с полем, что требует проверки на слух,
- никогда не выдавать придуманные значения за фактический разбор реальной песни.

Один демонстрационный пример с полностью выдуманными данными лежит в `Песни/_Пример разбора (демо).md` — он специально помечен как нереальная песня, чтобы показать формат, не создавая недостоверный "разбор" настоящей композиции.
